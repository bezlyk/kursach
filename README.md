# Мои подписки

Настольное приложение для курсовой работы «Разработка приложения для учёта и управления подписками на сервисы». Позволяет вести реестр сервисов, планировать расходы, видеть сроки оплаты и сохранять подтверждённые платежи. Интерфейс — на русском языке, все основные операции работают без Интернета.

**Технологии:** Python 3, Tkinter/ttk, SQLite (`sqlite3`), `Decimal`, `unittest`. Обязательных сторонних библиотек нет. PyCharm используется для разработки и запуска проекта.

## Возможности

- Добавление и редактирование сервиса, тарифа, категории, примечания, стоимости, периода, даты и статуса.
- Выбор даты в календаре в формах подписки, оплаты и возобновления; ручной ввод даты сохранён.
- До пяти активных подписок; неактивные записи сохраняются и не занимают места.
- Поиск русских названий без учёта регистра, совместные фильтры статуса и категории.
- Общая оценка расходов в месяц, независимая от фильтров списка.
- Напоминания о просроченных оплатах, оплатах сегодня и в ближайшие семь дней.
- Подтверждение уже выполненной оплаты, история подписки и фактические расходы за месяц.
- Календарный перенос дат: 31 января → конец февраля → 31 марта; восстановление 29 февраля в високосном году.
- Удаление с подтверждением только при отсутствии платежей; история защищена внешним ключом.
- Локальная база, сохранение после перезапуска и защита от второго экземпляра приложения.

## Запуск в PyCharm на Windows

1. Установите Python **3.12** с компонентом **Tcl/Tk and IDLE**. Он входит в обычную установку Python для Windows. Если Python уже установлен, проверьте Tkinter командой ниже.
2. Скачайте этот репозиторий или клонируйте его:

   ```text
   git clone https://github.com/bezlyk/kursach.git
   ```

3. В PyCharm выберите **File → Open** и откройте папку `kursach`, в которой лежит `main.py`.
4. В **Settings → Project → Python Interpreter** выберите установленный Python 3.12 либо создайте виртуальное окружение `.venv` на его основе. Устанавливать пакеты через pip не требуется.
5. Откройте `main.py`, нажмите правой кнопкой мыши и выберите **Run 'main'**. Откроется окно «Мои подписки».
6. Для тестов откройте Terminal в PyCharm и выполните `python -m unittest discover -s tests -v`.

Названия пунктов меню могут немного отличаться в разных версиях PyCharm. При первом запуске список пустой: нажмите «+ Добавить». Пример данных для ручного ввода: сервис «Музыка», стоимость `300,00`, период «Месяц», плановая дата в формате `ДД.ММ.ГГГГ`.

## Запуск из терминала

Из папки проекта:

```text
python --version
python -m tkinter
python main.py
```

`python -m tkinter` должен открыть диагностическое окно Tcl/Tk. Закройте его перед запуском приложения. В Windows можно использовать `py -3.12` вместо `python`, в Linux — `python3`.

В Linux для запуска нужен графический рабочий стол и системный пакет Tkinter (например, `python3-tk` для Debian/Ubuntu). При отсутствии Tkinter или графического экрана `main.py` выводит понятное сообщение. Виртуальный экран нужен только для автоматических графических проверок на сервере.

**Фактически проверено:** Python 3.13.5, Tcl/Tk 8.6.16, SQLite 3.46.1 в Linux: 54 теста, включая настоящие окна Tkinter на виртуальном X-сервере. Дополнительно проверки выполнялись на Python 3.12.14 / Tk 9.0.4 / SQLite 3.53.1. В облачной сборке Tk 9 отсутствуют кириллические экранные шрифты, поэтому для визуальной проверки использован системный Python 3.13 с Tk 8.6. В этой облачной среде запускайте `/usr/bin/python3 main.py` при доступном графическом экране. Запуск в локальном PyCharm и Windows здесь не выполнялся; для него подготовлен [чек-лист](docs/manual-checks.md).

## Как пользоваться

На вкладке **«Мои подписки»** добавляйте сервисы и выбирайте строку для просмотра карточки. «Изменить» открывает все поля, «Отмена» оставляет базу прежней. Поиск и фильтры работают совместно; «Сбросить» возвращает полный список. Сводка вверху всегда относится ко всем активным подпискам.

Рядом с полями даты есть кнопка **«Календарь»**. Выберите месяц, год и день либо нажмите «Сегодня». Выбор заполняет поле в формате `ДД.ММ.ГГГГ`; сохранение выполняется кнопкой самой формы. Дату также можно набрать с клавиатуры. Отмена календаря оставляет введённый текст прежним.

На вкладке **«К оплате»** показаны сроки с текстовыми пояснениями. «Открыть выбранную подписку» переводит к нужной карточке. Напоминания пересчитываются при запуске и изменениях данных. Кнопка «Обновить» убрана; если приложение оставалось открытым после смены дня, перезапустите его для пересчёта напоминаний.

**«Отметить оплату»** открывает форму с текущей стоимостью и сегодняшней датой. Проверьте сумму и фактическую дату, затем нажмите «Сохранить платёж». Это подтверждение учёта уже выполненной оплаты. Программа не списывает деньги. Следующая дата сдвигается ровно на один период от прежней плановой даты, поэтому при большой задержке она может остаться просроченной. Для следующего оплаченного периода нужно открыть новую форму и подтвердить его отдельно.

**«История»** показывает все платежи выбранной подписки. На вкладке **«Фактические расходы»** выберите месяц и год и нажмите «Показать». Итог считается по фактическим датам, включая платежи неактивных подписок.

**«Сделать неактивной»** освобождает место и сохраняет историю. **«Возобновить»** позволяет проверить следующую дату. Эти действия не отключают и не возобновляют услугу у поставщика — это нужно сделать отдельно. Удалить можно только подписку без платежей.

## Расчёты и хранение

Стоимость и платежи хранятся в **целых копейках**. Допустимо от `0,01` до `99 999,99` рубля, не более двух знаков после запятой или точки. Название обязательно, до 100 символов; тариф — до 100, категория — до 50, примечание — до 500. Слишком длинный ввод отклоняется с пояснением.

Оценка расходов в месяц = сумма месячных стоимостей + сумма годовых стоимостей / 12. Округляется только общий результат по `ROUND_HALF_UP`. Например, 300 руб./месяц и 1200 руб./год дают 400 руб./месяц. Фактические расходы — отдельная сумма подтверждённых платежей.

Файл базы автоматически создаётся по пути **`data/subscriptions.sqlite3` относительно `main.py`**, а не относительно терминала. При первом запуске демонстрационные записи не создаются. Рядом находится технический файл `.lock`. Блокировку удерживает операционная система; после закрытия или аварии процесса она освобождается, даже если файл `.lock` остался. Удалять его во время работы программы нельзя.

Для переноса данных закройте приложение и скопируйте **всю папку проекта вместе с `data`**. Для резервной копии закройте программу и сохраните папку `data` отдельно. При клонировании с GitHub личная база не скачивается: база, временные файлы, `.venv` и настройки `.idea` исключены из Git.

В базе две таблицы: `subscriptions` и `payments`, связь «одна подписка — много платежей». Включены внешние ключи, проверки диапазонов и уникальность пары «подписка + плановая дата». Лимит активных записей дополнительно защищён триггерами SQLite. Запись платежа и перенос даты выполняются одной транзакцией. Ошибка записи откатывает оба изменения.

## Структура и подготовка к защите

```text
main.py                    точка входа, путь к базе, запуск и завершение
subscriptions/
    domain.py              модели, проверки, деньги, календарь, напоминания
    database.py            схема SQLite, запросы и транзакции
    service.py             операции учёта и бизнес-правила
    instance.py            блокировка одного экземпляра для файла базы
    ui.py                  главное окно и вкладки
    dialogs.py             формы подписки, оплаты, активации и истории
    widgets.py             общие таблицы и элементы интерфейса
tests/                     автоматические проверки во временных базах
docs/requirements.md       соответствие исходному документу
docs/manual-checks.md      проверка на пользовательском компьютере
```

На защите удобно разобрать оплату: окно получает явное подтверждение → сервис проверяет активность, сумму, дату и оплачиваемый период → вычисляет следующую дату с сохранением исходного дня графика → база сохраняет платёж и дату одной транзакцией → интерфейс обновляет сведения. Повторный запрос из старой формы отклоняется, а уникальное ограничение защищает историю даже после ручной смены графика.

## Проверки

```text
python -m unittest discover -s tests -v
```

Тесты создают отдельные временные базы и не открывают пользовательский файл. Дата в сценариях задана явно. Проверяются лимит и повторная активация, валидация полей, точность сумм, напоминания, високосные годы, поздние оплаты, повторное подтверждение, откат при сбоях, защита истории, повторное открытие базы, поиск, формы и отмена действий. Отдельные процессы проверяют блокировку и её освобождение после аварийного завершения.

Графические тесты выполняются при доступном экране и Tkinter. Без экрана они помечаются **skipped**, это не проверка интерфейса. Тесты логики и хранения можно запустить отдельно:

```text
python -m unittest tests.test_domain tests.test_service tests.test_instance -v
```

Для Linux CI с установленным Xvfb можно использовать `xvfb-run -a python -m unittest discover -s tests -v`. В текущей облачной среде вместо Xvfb использован Xorg с виртуальным dummy-драйвером.

## Границы версии

Один пользователь, один локальный профиль и один экземпляр программы для файла базы. Валюта — рубль, периоды — месяц и год. Регистрация, синхронизация, банковские операции, автоматическая оплата, фоновые уведомления, веб- и мобильная версии не предусмотрены. Прошлые платежи доступны для просмотра и не редактируются. Автоматического резервного копирования нет.
