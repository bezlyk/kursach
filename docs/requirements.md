# Соответствие требованиям

Основа реализации — прочитанный файл «Требования_к_приложению_учёта_подписок.docx» и сопровождающий «Промпт_Codex_приложение_подписки.txt». Коды ниже взяты из исходного документа. Приложение настольное, однопользовательское, на Python/Tkinter/SQLite; обязательных сторонних зависимостей нет.

## Бизнес-требования

| Код | Реализация | Проверка |
| --- | --- | --- |
| БТ-01 | Реестр и полная карточка подписки | `test_ui`: добавление, редактирование, выбор карточки |
| БТ-02 | Общая месячная оценка по всем активным записям | `test_service`: месячные, годовые и смешанные суммы, округление итога |
| БТ-03 | Вкладка «К оплате»: просрочка, сегодня, до 7 дней | `test_service`: границы −1, 0, 7, 8; `test_ui`: переход к подписке |
| БТ-04 | Подтверждённые платежи отдельно от оценки | `test_service`: месяц по фактической дате; `test_ui`: таблица и итог |
| БТ-05 | Деактивация с сохранением записей и платежей | `test_service`, `test_ui`: история остаётся, оценка исключает запись |
| БТ-06 | Локальная SQLite, без сетевых операций в приложении | `test_service`: повторное открытие базы; `test_instance`: фиксированный путь |

## Объём фактической проверки

Автоматические тесты используют только временные базы. Выполнены проверки логики, SQLite и реальных виджетов/диалогов Tkinter на виртуальном X-сервере в Linux. Отдельно проверяются запуск точки входа, повторное открытие и отказ второго экземпляра. Это не заменяет проверку оформления при пользовательском масштабе экрана и реальный запуск в Windows/PyCharm. Такие шаги перечислены в ручном чек-листе. При запуске тестов без графического экрана UI-сценарии отмечаются как пропущенные.
