# Проверка в PyCharm на Windows

Автоматические графические проверки выполнены в Linux. Следующий короткий сценарий проверяет установку Python/Tkinter, окно и особенности Windows на вашем компьютере.

Для безопасной проверки используйте отдельную копию папки проекта без личной папки `data`. В рабочей копии с вашей базой не удаляйте данные ради проверки.

1. Откройте проект в PyCharm, выберите Python 3.12. Выполните `python -m tkinter`, затем запустите `main.py`. Должны появиться пустой список, «0 из 5» и «0,00 руб.».
2. Добавьте месячный сервис за 300 руб. с датой `31.01.2027` и годовой за 1200 руб. Сводка — «2 из 5» и «400,00 руб.». При желании замените годы примера на уже прошедшие относительно даты компьютера.
3. Откройте редактирование, поменяйте название и нажмите «Отмена»: данные прежние. Повторите с сохранением. Введите сумму `1,234`, несуществующую дату и пустое название: получите русские пояснения, после исправления форма должна сохраниться.
4. Найдите русское название в другом регистре, примените категорию и статус одновременно. Сводка не меняется. Проверьте отсутствие совпадений и сброс фильтров.
5. Выберите просроченную подписку, нажмите «Отметить оплату». Проверьте сумму и дату. Будущая фактическая дата не сохраняется. Сохраните корректный платёж: он появляется в истории, дата `31.01.2027` меняется на `28.02.2027`, при следующем подтверждении — на `31.03.2027`. После первой оплаты для следующего периода нужно заново открыть форму.
6. На вкладке «Фактические расходы» выберите месяц фактической оплаты и нажмите «Показать»: сумма совпадает с историей. В месяце без платежей итог нулевой. Сделайте подписку неактивной: платёж остаётся, оценка и напоминания её исключают.
7. Доведите число активных подписок до пяти. Шестая и активация дополнительной записи должны отклоняться. Обычное редактирование одной из пяти разрешено. Деактивируйте одну и возобновите другую, изменив следующую дату.
8. Удалите запись без платежей: сначала отмените подтверждение, затем подтвердите. Удаление записи с историей должно отклоняться с предложением сделать её неактивной.
9. Уменьшите окно до минимального размера, проверьте доступность кнопок, прокрутку таблиц и длинного примечания. Проверьте масштаб Windows 100% и тот, которым обычно пользуетесь.
10. Оставив приложение открытым, запустите `main.py` повторно: должно появиться сообщение о втором экземпляре. Закройте оба окна. Снова запустите программу — сведения сохранились. В тестовой копии можно завершить процесс через диспетчер задач и проверить, что повторный запуск не заблокирован навсегда.
11. Закройте программу и скопируйте всю папку с `data` в другое место. Запустите оттуда: сохранённые сведения доступны. Отключите Интернет — основные операции продолжают работать.
12. Запустите `python -m unittest discover -s tests -v`: на компьютере с экраном графические тесты должны исполняться, а не пропускаться.
13. В формах добавления, редактирования, оплаты и возобновления нажмите «Календарь». Выберите месяц, год и день: поле должно заполниться в формате `ДД.ММ.ГГГГ`, а запись в базу выполняется только после сохранения формы. Проверьте февраль високосного года, переход декабря в январь, «Сегодня», отмену и закрытие календаря клавишей Escape. После закрытия календаря форма должна оставаться доступной. Затем измените дату с клавиатуры и сохраните — ручной ввод работает как прежде. Будущая фактическая дата оплаты по-прежнему отклоняется.
14. В верхнем правом углу нет кнопки «Обновить». Список, сводка, история и напоминания обновляются после сохранения изменений. Если приложение оставалось открытым после смены дня, перезапустите его для пересчёта напоминаний.
